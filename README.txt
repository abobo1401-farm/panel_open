4×4 パネル画像公開システム v0.2.2
=================================
Firebase不要 / GitHub Pages向け

■ 今回の仕様
・表面：1枚画像＋4×4の境目あり
・表面文字：16パネル個別入力、初期値はすべて「？？？」
・裏面モードA：1枚絵。画像そのものは分割せず、開いた場所だけ見えるため境目なし
・裏面モードB：16枚個別画像。各マスは境目あり
・PNG / JPG / WebP対応
・画像はIndexedDBに保存
・文字・開閉状態などはlocalStorageに保存
・OBS画面と管理画面はBroadcastChannelで即時更新
・OBSの「操作」でパネルを直接クリック可能
・0.6秒程度のめくりアニメーション
・全16枚で同じ内蔵効果音
・効果音の音量調整、試聴あり

■ おすすめの使い方（重要）
GitHub Pagesへアップロード後、
1. obs.html をOBSの「ブラウザ」ソースに登録
2. admin.html をOBSの「カスタムブラウザドック」に登録
3. カスタムブラウザドック側で画像・文字を設定
4. ブラウザソースを右クリック →「操作」でパネルを直接クリック

OBSのブラウザソースとカスタムブラウザドックはOBS内の同じWeb環境で扱えるため、
Firebaseなしでも同じoriginの保存データを共有して使う構成です。

※普通のChromeでadmin.htmlを開いた場合、OBSとは別ブラウザ環境なので、
  Chrome側に保存した画像がOBSへ共有されない場合があります。
  GitHub Pagesのみで確実に使う場合は「OBSカスタムブラウザドック」で設定してください。

■ GitHub Pages URL例
https://ユーザー名.github.io/リポジトリ名/admin.html
https://ユーザー名.github.io/リポジトリ名/obs.html

■ 保存について
画像はGitHubへアップロードされません。
利用者それぞれのOBS内ブラウザ保存領域（IndexedDB）へ保存されます。
OBSのブラウザキャッシュやサイトデータを削除すると画像が消える可能性があります。

・管理画面で既に開いているマスをクリックすると、そのパネルを閉じて元に戻す


v0.2.2: OBS表示側で、OBS直接クリック・管理画面からの開操作の両方にめくりアニメーションと共通SEが確実に再生されるよう修正。

v0.2.4 修正:
- 管理画面からパネルを開いた場合もOBS側でSEが再生されるよう、flip.wavをOBS側で直接再生する方式に変更。
- 管理画面側では開く操作時のSEを鳴らさず、OBS側だけで鳴るようにして二重再生を防止。


v0.2.5
- 管理画面のパネル開閉アニメーションを廃止（即時反映）
- 管理画面ではSEを再生しない
- 管理画面から開いた場合もOBS側ではめくりアニメーション＋SEを再生
- OBS用SE音量設定は管理画面に残す


v0.2.6（SE頭切れ修正）
- 効果音の再生をHTMLAudioからWeb Audio APIへ変更。
  flip.wavを起動時にデコードしてメモリ上に保持するため、1枚目から遅延なく鳴る。
- obs.html 起動時に無音を1回再生してオーディオ出力を起動（プライミング）。
  「一番初めの音だけ聞こえづらい／頭が切れる」現象の対策。
- ソースの非表示→表示のたびに再プライミング。
- flip.wav をノーマライズ（ピーク約13% → 約89%）。音量そのものが小さかったため。
  ※旧wavをそのまま使う場合は app.js の FLIP_GAIN を 3.0〜5.0 に変更してください。
- Web Audioが使えない環境では従来のHTMLAudio再生に自動フォールバック。

【OBS側の確認事項】
- ブラウザソースのプロパティで「表示されていないときにソースをシャットダウンする」を
  OFFにしておくと、シーン切替直後の1発目も確実に鳴ります。
- 「OBSで音声を制御する」をONにすると、OBSのミキサーに音量フェーダーが出ます。
