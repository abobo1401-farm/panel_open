4×4 パネル画像公開システム v0.2.2
=================================
Firebase不要 / GitHub Pages向け

■ 今回の仕様
・表面：1枚画像＋4×4の境目あり
・表面文字：16パネル個別入力、初期値はすべて「？？？」
・裏面モードA：1枚絵。画像そのものは分割せず、開いた場所だけ見えるため境目なし
・裏面モードB：16枚個別画像。各マスは境目あり
・PNG / JPG / WebP対応
・画像はIndexedDBに保存
・文字・開閉状態などはlocalStorageに保存
・OBS画面と管理画面はBroadcastChannelで即時更新
・OBSの「操作」でパネルを直接クリック可能
・0.6秒程度のめくりアニメーション
・全16枚で同じ内蔵効果音
・効果音の音量調整、試聴あり

■ おすすめの使い方（重要）
GitHub Pagesへアップロード後、
1. obs.html をOBSの「ブラウザ」ソースに登録
2. admin.html をOBSの「カスタムブラウザドック」に登録
3. カスタムブラウザドック側で画像・文字を設定
4. ブラウザソースを右クリック →「操作」でパネルを直接クリック

OBSのブラウザソースとカスタムブラウザドックはOBS内の同じWeb環境で扱えるため、
Firebaseなしでも同じoriginの保存データを共有して使う構成です。

※普通のChromeでadmin.htmlを開いた場合、OBSとは別ブラウザ環境なので、
  Chrome側に保存した画像がOBSへ共有されない場合があります。
  GitHub Pagesのみで確実に使う場合は「OBSカスタムブラウザドック」で設定してください。

■ GitHub Pages URL例
https://ユーザー名.github.io/リポジトリ名/admin.html
https://ユーザー名.github.io/リポジトリ名/obs.html

■ 保存について
画像はGitHubへアップロードされません。
利用者それぞれのOBS内ブラウザ保存領域（IndexedDB）へ保存されます。
OBSのブラウザキャッシュやサイトデータを削除すると画像が消える可能性があります。

- 「OBSで音声を制御する」をONにすると、OBSのミキサーに音量フェーダーが出ます。


v0.2.7（SEが たまに鳴らない 問題の修正）
原因は3つとも「SE再生がアニメーション処理に巻き込まれていた」こと。
1) animating ロック中に届いた開操作は、音も出さずに状態だけ差し替えていた
   → 0.68秒以内に2枚目を開くと2枚目のSEが完全に消えていた
2) 再描画の途中に開操作が届くと、対象タイルが見つからず targets が空になり、
   SEを鳴らす行の手前で return していた
3) BroadcastChannelとstorageイベントの二重配信を animating ロックで
   偶然吸収していたため、ロックを外すと今度は二重再生になる構造だった

対策
- SEの再生を、状態差分を検出した直後・無条件に実行するよう分離。
  アニメーションの成否、タイルの有無、描画中かどうかに一切影響されない。
- 二重再生は「先に state を確定してから差分を取る」方式で防止。
  同じ変更が2経路で届いても2回目は差分ゼロになる。
- めくり済みタイルは .opening のまま残す方式に変更（.open と最終形が同じ）。
  めくり後の強制再描画が不要になり、連打しても取りこぼさない。
- AudioContextが一時停止していた場合は resume 完了後に再生するよう変更。
